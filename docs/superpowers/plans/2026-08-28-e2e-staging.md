# E2E sobre staging — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que cada push a `develop` ejercite el panel en un navegador real contra staging, y que un rojo impida desplegar ese commit a producción.

**Architecture:** Playwright vive en `apps/admin-v2/e2e/` y corre contra `https://staging.goturnly.com`. Un workflow nuevo espera a que el admin desplegado coincida con el commit (ruta `/api/version`), resetea la base por SSH (`migrate:fresh` + `staging:seed`), corre los tests con un solo worker y sube el trace al fallar. `deploy-prod.yml` gana un primer paso que consulta la conclusión de esa corrida para el mismo SHA.

**Tech Stack:** `@playwright/test` (Chromium), Next.js 16 App Router (route handler), GitHub Actions, SSH a `turnly-staging`, Laravel Artisan.

**Spec:** `docs/superpowers/specs/2026-08-28-e2e-staging-design.md`

## Global Constraints

- Todo el código de E2E vive bajo `apps/admin-v2/`; los comandos se corren desde ese directorio.
- Este repo es **Next.js 16**. Antes de escribir código de Next, leer la guía correspondiente en `apps/admin-v2/node_modules/next/dist/docs/`. El `AGENTS.md` de `apps/admin-v2/` tiene más detalle.
- URL base por defecto: `https://staging.goturnly.com`, sobreescribible con `E2E_BASE_URL`.
- API de staging: `https://api.staging.goturnly.com`.
- Credenciales sembradas (no son secreto, staging es un sandbox): `cajero@autospa-demo.staging.goturnly.com` y `admin@autospa-demo.staging.goturnly.com`, contraseña `staging1234`.
- `workers: 1` y `fullyParallel: false`. La base es compartida.
- Prohibido `page.waitForTimeout`. Sólo la espera automática de locators y `expect`.
- `retries: 1` sólo en CI.
- Secretos de GitHub que ya existen y se reusan: `STAGING_DEPLOY_HOST`, `STAGING_DEPLOY_USER`, `STAGING_DEPLOY_SSH_KEY`. No se crea ninguno nuevo.
- Ruta del backend en el box de staging: `/var/www/turnly/apps/backend`.
- El seed reparte registros sobre 18 días: **hoy ya tiene filas**. Ningún test afirma totales del día.

Crear `apps/admin-v2/e2e/fixtures/roles.ts`:

```ts
/**
 * Las cuentas que siembra `staging:seed`. Un login por rol, con el correo
 * que arma el comando: `{rol}@{slug}.staging.goturnly.com`.
 *
 * La contraseña no es un secreto: staging es un sandbox y el propio seed la
 * imprime al terminar. Tratarla como secreto sólo agrega ceremonia.
 */
export const TENANT = 'autospa-demo';
export const STAFF_PASSWORD = 'staging1234';

export type RoleName = 'cajero' | 'admin';

export type Role = {
  name: RoleName;
  identifier: string;
  password: string;
  storageState: string;
};

export const ROLES: readonly Role[] = [
  {
    name: 'cajero',
    identifier: `cajero@${TENANT}.staging.goturnly.com`,
    password: STAFF_PASSWORD,
    storageState: 'e2e/.auth/cajero.json',
  },
  {
    name: 'admin',
    identifier: `admin@${TENANT}.staging.goturnly.com`,
    password: STAFF_PASSWORD,
    storageState: 'e2e/.auth/admin.json',
  },
] as const;

export function authFor(name: RoleName): string {
  const role = ROLES.find((r) => r.name === name);
  if (!role) {
    throw new Error(`Rol desconocido: ${name}`);
  }
  return role.storageState;
}
```

- [ ] **Step 4: Escribir el setup de sesión**

Crear `apps/admin-v2/e2e/setup/auth.setup.ts`:

```ts
import { test as setup, expect } from '@playwright/test';

import { ROLES } from '../fixtures/roles';

/**
 * Entra una vez por rol y guarda el estado. El panel guarda el token Y el
 * slug del tenant en `localStorage`, así que el storageState alcanza: los
 * specs arrancan adentro, sin repetir el login en cada test.
 */
for (const role of ROLES) {
  setup(`sesión de ${role.name}`, async ({ page }) => {
    await page.goto('/login');

    await page.getByLabel('Usuario o correo').fill(role.identifier);
    await page.getByLabel('Contraseña').fill(role.password);
    await page.getByRole('button', { name: 'Iniciar sesión' }).click();

    // No se afirma una ruta concreta: el destino depende del rol y de la
    // matriz. Lo que importa es haber salido del login.
    await page.waitForURL((url) => !url.pathname.startsWith('/login'), {
      timeout: 30_000,
    });

    await expect(page.getByText('Iniciar sesión')).toHaveCount(0);

    await page.context().storageState({ path: role.storageState });
  });
}
```

### Task 2: El workflow que los corre

**Files:**
- Create: `.github/workflows/e2e-staging.yml`

**Interfaces:**
- Consumes: `GET /api/version` (Task 1), `npm run e2e` (Task 1), secretos `STAGING_DEPLOY_*`.
- Produces: workflow llamado **`E2E Staging`** — el nombre exacto importa: Task 5 lo busca por el archivo `e2e-staging.yml`.

- [ ] **Step 1: Escribir el workflow**

Crear `.github/workflows/e2e-staging.yml`:

```yaml
name: E2E Staging

# Sub-proyecto 2 de docs/superpowers/specs/2026-08-28-e2e-staging-design.md.
#
# Dos disparos, y los dos hacen falta. `Deploy Staging (backend)` sólo corre
# con cambios en apps/backend/**; un cambio puro de admin —de donde salieron
# los tres bugs que motivaron todo esto— no lo dispara, y con workflow_run
# como único trigger nunca se probaría.

on:
  workflow_run:
    workflows: ['Deploy Staging (backend)']
    types: [completed]
  push:
    branches: [develop]
    paths:
      - 'apps/admin-v2/**'
      - '.github/workflows/e2e-staging.yml'
  workflow_dispatch:

concurrency:
  group: e2e-staging
  cancel-in-progress: false

env:
  BASE_URL: https://staging.goturnly.com
  API_URL: https://api.staging.goturnly.com

jobs:
  e2e:
    # Un deploy de staging en rojo no deja nada que probar.
    if: github.event_name != 'workflow_run' || github.event.workflow_run.conclusion == 'success'
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: apps/admin-v2

    steps:
      - name: Resolver el commit a probar
        id: commit
        working-directory: .
        run: |
          set -euo pipefail
          if [ "${{ github.event_name }}" = "workflow_run" ]; then
            sha="${{ github.event.workflow_run.head_sha }}"
          else
            sha="${{ github.sha }}"
          fi
          echo "sha=$sha" >> "$GITHUB_OUTPUT"
          echo "Commit bajo prueba: $sha"

      - uses: actions/checkout@v4
        with:
          ref: ${{ steps.commit.outputs.sha }}

      - uses: actions/setup-node@v4
        with:
          node-version: 24
          cache: npm
          cache-dependency-path: apps/admin-v2/package-lock.json

      - name: Esperar a que Vercel publique este commit
        working-directory: .
        run: |
          set -euo pipefail
          want="${{ steps.commit.outputs.sha }}"
          for i in $(seq 1 60); do
            got=$(curl -sf -m 15 "$BASE_URL/api/version" | jq -r '.sha' || echo '')
            if [ "$got" = "$want" ]; then
              echo "Admin desplegado en $want"
              exit 0
            fi
            echo "intento $i: el admin sirve '$got', se espera '$want'"
            sleep 5
          done
          echo "::error::Vercel no publicó $want en 5 minutos"
          exit 1

      - name: Chequear la API de staging
        working-directory: .
        run: |
          set -euo pipefail
          code=$(curl -s -o /dev/null -m 20 -w '%{http_code}' "$API_URL/up")
          [ "$code" = "200" ] || { echo "::error::/up devolvió $code"; exit 1; }

      - name: Setup SSH
        working-directory: .
        run: |
          mkdir -p ~/.ssh
          echo "${{ secrets.STAGING_DEPLOY_SSH_KEY }}" > ~/.ssh/deploy_key
          chmod 600 ~/.ssh/deploy_key
          ssh-keyscan -H ${{ secrets.STAGING_DEPLOY_HOST }} >> ~/.ssh/known_hosts

      - name: Base nueva
        working-directory: .
        run: |
          set -euo pipefail
          ssh -i ~/.ssh/deploy_key \
            ${{ secrets.STAGING_DEPLOY_USER }}@${{ secrets.STAGING_DEPLOY_HOST }} bash <<'ENDSSH'
            set -euo pipefail
            cd /var/www/turnly/apps/backend

            # Sin esto, cada corrida deja sedimento —tickets a medio cobrar,
            # cajas abiertas de la anterior— y el punto de partida cambia.
            php artisan migrate:fresh --force
            php artisan staging:seed
          ENDSSH

      - name: npm ci
        run: npm ci

      - name: Instalar Chromium
        run: npx playwright install --with-deps chromium

      - name: Correr los E2E
        run: npm run e2e
        env:
          E2E_BASE_URL: ${{ env.BASE_URL }}

      - name: Subir el diagnóstico
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: |
            apps/admin-v2/playwright-report/
            apps/admin-v2/test-results/
          retention-days: 14
```

```ts
import { test, expect, type Page } from '@playwright/test';

import { authFor } from '../fixtures/roles';

test.use({ storageState: authFor('cajero') });

async function abrirModal(page: Page) {
  await page.goto('/service-log');
  await page.getByRole('button', { name: 'Registrar servicio' }).click();
  await expect(page.getByRole('heading', { name: 'Nuevo Servicio' })).toBeVisible();
}

/**
 * El bug del 20 de agosto: un ticket de sólo producto exigía un vehículo que
 * no existía, y el cajero terminaba inventando uno. Se registra suelto.
 */
test('una venta de sólo producto se registra sin vehículo', async ({ page }) => {
  await abrirModal(page);

  await page.getByRole('combobox', { name: /Agregar producto/i }).click();
  const producto = page.getByRole('option').first();
  const nombreProducto = (await producto.textContent())?.trim() ?? '';
  await producto.click();

  expect(nombreProducto).not.toBe('');

  await page.getByRole('button', { name: 'Registrar Servicio' }).click();

  await expect(page.getByText('Venta registrada')).toBeVisible();

  // El ticket recién creado encabeza la lista del día. Se afirma sobre él, no
  // sobre totales: el seed ya dejó filas de hoy antes de que el test corriera.
  await page.goto('/service-log');
  // El detalle vive en /service-log/<id>; el enlace es el ancla más estable
  // que ofrece la lista hoy.
  await page.locator('a[href^="/service-log/"]').first().click();

  await expect(page.getByText('Sin recurso')).toBeVisible();
  await expect(page.getByText('Sin cliente')).toBeVisible();
});

/**
 * La otra mitad, que el arreglo no podía romper: un servicio se presta sobre
 * algo. La UI no ofrece el selector de servicios hasta que hay vehículo.
 */
test('un servicio no se puede agregar sin vehículo', async ({ page }) => {
  await abrirModal(page);

  await expect(
    page.getByText('Selecciona o crea un cliente arriba para empezar a agregar'),
  ).toBeVisible();

  await expect(page.getByRole('combobox', { name: /Selecciona un servicio/i })).toHaveCount(0);
});
```

```ts
import { test, expect } from '@playwright/test';

import { authFor, PLATE_PREFIX } from '../fixtures/roles';

test.use({ storageState: authFor('admin') });

// El separador decimal no es lo que este test cuida: cuida que los centavos
// existan. Aceptar los dos evita un rojo el día que se cambie el formateo.
const CUATRO_VEINTICINCO = /\$\s?4[.,]25/;

/**
 * El bug de agosto: `MoneyInput` era un `type=number` con `value` numérico, y
 * teclear 4.25 metía 2425 en la base. Nadie se enteraba hasta el arqueo.
 */
test('un precio con centavos sobrevive el viaje entero', async ({ page }) => {
  await page.goto('/service-log');
  await page.getByRole('button', { name: 'Registrar servicio' }).click();
  await expect(page.getByRole('heading', { name: 'Nuevo Servicio' })).toBeVisible();

  // Un vehículo del seed: sin él, el panel no ofrece el selector de servicios.
  await page.getByPlaceholder(/placa/i).fill(PLATE_PREFIX);
  await page.getByRole('option').first().click();

  await page.getByRole('combobox', { name: /Selecciona un servicio/i }).click();
  await page.getByRole('option').first().click();

  const precio = page.getByLabel('Precio unitario');
  await precio.fill('');
  // `pressSequentially`, nunca `fill`: `fill` asigna el valor de golpe y el
  // bug sólo aparece tecla por tecla. Un test con `fill` habría pasado en
  // verde sobre el bug.
  await precio.pressSequentially('4.25', { delay: 60 });

  await expect(precio).toHaveValue('4.25');

  await page.getByRole('button', { name: 'Registrar Servicio' }).click();
  await expect(page.getByText('Servicio registrado')).toBeVisible();

  await page.goto('/service-log');
  await expect(page.getByText(CUATRO_VEINTICINCO).first()).toBeVisible();

  await page.getByText(CUATRO_VEINTICINCO).first().click();
  await expect(page.getByText(CUATRO_VEINTICINCO).first()).toBeVisible();
});
```

**Files:**
- Modify: `.github/workflows/deploy-prod.yml` (agregar un primer step al job `deploy`)

**Interfaces:**
- Consumes: el workflow `e2e-staging.yml` (Task 2).
- Produces: nada.

- [ ] **Step 1: Agregar el paso**

En `.github/workflows/deploy-prod.yml`, insertar **antes** del step `Setup SSH`:

```yaml
      # Sub-proyecto 2: prod no despliega un commit que los E2E no aprobaron.
      #
      # Hoy `develop` entra a `main` por fast-forward, así que el SHA es el
      # mismo y la corrida existe. El día que `main` reciba un merge commit no
      # va a haber corrida para ese SHA y este paso va a fallar con el motivo:
      # se destraba con workflow_dispatch, que es la salida de emergencia.
      - name: E2E de staging en verde para este commit
        if: github.event_name != 'workflow_dispatch'
        env:
          GH_TOKEN: ${{ github.token }}
        run: |
          set -euo pipefail

          for i in $(seq 1 40); do
            estado=$(gh run list --repo "$GITHUB_REPOSITORY" \
              --workflow e2e-staging.yml --commit "$GITHUB_SHA" \
              --json status,conclusion \
              --jq '[.[]][0] | "\(.status):\(.conclusion // "")"' || echo 'none:')

            case "$estado" in
              completed:success)
                echo "E2E en verde para $GITHUB_SHA"
                exit 0
                ;;
              completed:*)
                echo "::error::Los E2E de $GITHUB_SHA terminaron en ${estado#completed:}. Prod no se despliega."
                exit 1
                ;;
              none:)
                echo "::error::No hay corrida de E2E para $GITHUB_SHA. Si es a propósito, desplegá con workflow_dispatch."
                exit 1
                ;;
              *)
                echo "intento $i: los E2E están en '$estado', esperando"
                sleep 15
                ;;
            esac
          done

          echo "::error::Los E2E de $GITHUB_SHA no terminaron en 10 minutos."
          exit 1
```

- [ ] **Step 2: Verificar el caso feliz**

```bash
git add .github/workflows/deploy-prod.yml
git commit -m "ci(prod): no desplegar un commit que los E2E no aprobaron"
git push origin develop
```

Esperar a que `E2E Staging` termine en verde para ese commit, después:

```bash
git checkout main && git merge --ff-only develop && git push origin main
gh run watch $(gh run list --workflow deploy-prod.yml --limit 1 --json databaseId --jq '.[0].databaseId') --exit-status
git checkout develop
```

Esperado: el paso del semáforo imprime "E2E en verde para <sha>" y el deploy sigue como siempre.
